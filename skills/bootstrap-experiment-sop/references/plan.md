# Plan the experiment

Part of the [experiment SOP](../SKILL.md), whose rules on links, the read-only plugin, and publishing apply here. Resolve links relative to this file; the plugin root is three directories above it.

Read [the experiment protocol](../../../docs/experiment-protocol.md). Use [the report template](../../../experiments/TEMPLATE.md).

Turn the supplied platform and goal into a versioned experiment contract. Discover the actual machine and existing toolchain read-only; distinguish measured capabilities from assumptions. Identify the builder LLM separately from the target model and distinguish development from evaluation harnesses.

Resolve the model/weight/tokenizer and harness versions, permitted dependencies/code reuse, baseline selection, numerical checks, quality/resource limits, experiment budget, and stopping rule. Select the evaluation (workload, application checks, timing definitions) from `evaluations/` by id, repository revision, and definition hash, following [the evaluation protocol](../../../docs/evaluation-protocol.md). Never define or edit evaluation code, workload, or scoring inside an experiment, and do not use a draft evaluation for formal runs; if no released evaluation fits, stop and ask for one to be added to this repository. Define which metric “competitive” refers to and numerical criteria before tuning. Use dated primary sources to identify strong platform baselines; do not assume prior Infer.NET results establish current SOTA.

Mark missing essential fields as unresolved and obtain the information needed before dependent execution. Do not silently pick different hardware, precision, model, or thresholds. Publish a plan with a fixed skill revision and a concrete build/evaluation task. Keep preparation within the user's authorized scope; this reference does not itself authorize costly runs or operating-system changes.

Hand the frozen contract to [the build reference](build.md). To vary an existing experiment, write a derived contract that extends a pinned base instead of copying it (see [the derived experiment steps](derived-experiment.md)); everything except the target model may be overridden, and the resolved effective contract is what freezes. For a new experiment, see [the new experiment steps](new-experiment.md). Check a JSON contract's shape against the `ExperimentContract` schema in [the protocol schema](../../../schema/experiment-protocol.openapi.json) when a validator is available; a frozen contract has no null fields. The schema checks structure only and does not replace the protocol. A plan is not a measured result.
