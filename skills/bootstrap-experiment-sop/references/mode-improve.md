# Mode: Improve an experiment

Stages 1 and 2 of the [experiment SOP](../SKILL.md) for the next step of a hill climb: a new engine commit, an added engine, or a changed goal, keeping the target model. Resolve links relative to this file. The rules for derived experiments are in [the experiment protocol](experiment-protocol.md).

**A base experiment is required.** Improve derives from an existing frozen experiment, pinned by `extends_path`, `extends_revision`, and `extends_sha256`. Without one, use [Add an engine](mode-add-engine.md). If nothing in the contract changes, use [Evaluate](mode-evaluate.md). If the target model changes, use [Add an engine](mode-add-engine.md).

1. **Pin the base.** Record the base experiment's path, full commit, and file hash. The base must be a frozen experiment. Read its evaluation reports first: if it has none, say that the derived experiment has no evidence to improve on.
2. **Find the gap.** State which result in the base motivates the change, and quote the base evidence for it. The hypothesis must come from that evidence, not from preference. A regression in the base is as valid a starting point as a shortfall.
3. **Define the delta.** Write one hypothesis and the smallest set of overrides that tests it. Typical overrides are `engine_commit` (the next commit), `engine_name` (another engine), and `goal_thresholds`. The target model cannot be overridden; if the user wants another model, stop and use [Add an engine](mode-add-engine.md). Prefer changing one thing so a difference can be attributed to it; if several change, list them and state that the result cannot be attributed to any one of them.
4. **Get the engine.** The effective `engine_commit` must exist before the freeze. Build or set up the engine as in [Add an engine](mode-add-engine.md).
5. **Write the derived experiment.** Create `experiments/<experiment-id>/experiment.json` with its own `experiment_id`, `status`, `description`, and `contract_frozen_at`, the base pinned by `extends_path`, `extends_revision`, and `extends_sha256`, and the overridden fields at the top level. Do not copy the base.
6. **Check it.** Run the check command from [the SOP](../SKILL.md). Show the user the list of changes it prints and confirm that it is exactly the intended delta. A misspelled override field or an unresolved field in the effective experiment must be fixed, not ignored.
7. **Plan the comparison.** Results are not inherited. To compare with the base, compare the reports of the two experiments: the derived experiment inherits the platform, the target model, and the evaluation, so only what you overrode differs. Re-measure the base if its reports were taken under other conditions. Keep matched comparisons separate from best-permitted-system comparisons.
8. **Freeze.** Commit the derived experiment on a codex/ branch and record its commit. Then go to [the evaluation reference](evaluate.md). In the results pull request, state what changed from the base, what stayed the same, and whether the conditions are matched.
